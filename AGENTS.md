# Prototype Instructions

Run the local server yourself and open the preview in the in-app browser. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## Durable Prototype Decisions

- В hero-секции фото поддонов и соответствующие текстовые блоки должны быть расположены симметрично относительно центра композиции и читаться как зеркальные пары.
- В desktop hero светлые новые поддоны должны быть увеличены и привязаны к верхнему левому углу, а тёмные б/у поддоны увеличены и привязаны к нижнему правому углу.
- В desktop hero новый поддон нужно сажать в свободную левую верхнюю зону над карточкой, а б/у поддон уводить в нижнюю правую зону под кнопкой и ниже строки преимуществ.
- В desktop hero белый новый поддон нужно дополнительно сдвигать на 50px вправо и на 50px выше относительно текущей позиции.
- В desktop hero изображение белого нового поддона внутри своего контейнера должно быть прижато к левому краю так же, как текст и кнопка под ним.
- В desktop hero контент новых поддонов: заголовок, подтекст и кнопку нужно ставить прямо под изображением паллеты, а не смещать вправо от него.
- В desktop hero контент новых поддонов должен быть собран в ровную левую колонку под белой паллетой: без центрирования текста и без кнопки, плавающей отдельно от текстового блока.
- В desktop hero блок б/у поддонов должен быть собран в один контейнер на правой стороне и идти сверху вниз в таком порядке: заголовок, описание, кнопка, изображение паллеты.
- В desktop hero весь контент внутри правого контейнера б/у поддонов: заголовок, описание, кнопка и изображение, должен быть прижат к правой стенке контейнера.
- В desktop hero контейнер б/у поддонов нужно дополнительно сдвигать на 200px вверх и на 5px влево относительно базовой позиции.
- В hero все преимущества нужно собирать в одну нижнюю стеклянную плашку; оставлять только самые важные пункты, выдерживать единый стиль, делать плашку почти прозрачной, с сильным blur и максимально скругленным бордером.
- В hero фоновую диагональную картинку подложки нужно уменьшать по высоте на 250px относительно полного размера секции.
- В desktop hero общую высоту секции и нижний отступ нужно поджимать так, чтобы под нижней стеклянной плашкой не оставался черный хвост body.
- В desktop hero нижнюю стеклянную плашку нужно поднимать ближе к основной композиции и убирать лишний нижний запас секции, чтобы между hero и плашкой не появлялся черный промежуток.
- В desktop hero нижняя стеклянная плашка преимуществ должна частично заходить на фото и основную композицию, а не стоять отдельным блоком на черном фоне под ней.
- В desktop header весь контент шапки: логотип, навигация и телефон, должен быть выровнен строго по вертикальному центру высоты хедера.
- В desktop header шапка должна читаться как отдельная сплошная черная полоса без лишнего черного хвоста страницы под hero.
- На странице выбора над hero-картинкой не должно оставаться чёрной горизонтальной плашки или пустого тёмного зазора между хедером и основной композицией.
- На странице выбора hero-композицию нужно поджимать вплотную под хедер, чтобы над фотографиями совсем не оставалось видимой чёрной полосы.
- На странице выбора общий фоновый складской/диагональный ассет нужно тянуть на весь `html/body`, а не только на контейнер hero или `.page`, чтобы за хедером и над фото не появлялись отдельные чёрные прослойки.
- На странице выбора диагональный фон должен читаться как одна чистая фоновая картинка без дополнительных CSS-наложений, из-за которых светлая сторона выглядит как отдельный объект или плашка.
- В desktop композиции hero-фон должен идти full-bleed на всю ширину окна без внешних черных полей и боковых отступов страницы.
- В desktop hero левый блок новых поддонов нужно дополнительно сдвигать примерно на 20px вправо, правый блок б/у поддонов на 20px влево и на 10px вверх, а обе паллеты увеличивать примерно на 50px.
- В desktop hero блок новых поддонов и правый блок контента б/у поддонов нужно дополнительно поджимать к центру примерно на 50px каждый.
- В desktop hero общую высоту страницы нужно держать на 200px выше текущей базовой высоты.
- В desktop hero нижняя плашка преимуществ не должна пересекаться ни с одним блоком паллет; на всех desktop-ширинах нужно держать минимум около 20px безопасного зазора до hero-контента.
- Для hero-фона нужно использовать более качественный исходник, если в проекте уже есть версия выше по разрешению той же композиции.
- В desktop hero обе паллеты нужно увеличивать так, чтобы они заметно выглядывали за левую и правую границы видимой области, сохраняя зеркальность композиции.
- В desktop header нужно поддерживать стиль референса с двумя строками у бренда и телефона: основная жирная строка и маленький приглушённый подзаголовок под ней.
- Для страницы новых поддонов верхний блок должен собираться как отдельный тёмный hero на фоне склада: крупный заголовок и CTA слева, большая светлая паллета справа.
- Для страницы новых поддонов фон верхнего hero-блока нужно делать светло-бежевым градиентом.
- Для страницы новых поддонов светло-бежевый градиент hero-блока нужно тянуть на всю ширину экрана, без тёмных полей по бокам.
- В каталоге новых поддонов названия карточек должны быть в формате размеров `120x80`, `114x114`, `120x100`, `120x120`, а отдельной карточкой должна идти `Заказать другой размер`.
- В карточках новых поддонов размер нужно выносить в название, а в параметрах показывать толщину доски.
- В детальном экране новых поддонов выбор толщины доски должен быть отдельным видимым переключателем с вариантами, а не одной статичной строкой в характеристиках.
- В детальном экране новых поддонов рядом с выбором толщины доски должен быть отдельный выбор верхнего настила: для `120x80` варианты `5 досок` и `6 досок`, для `120x100` и `120x120` варианты `5 досок`, `6 досок`, `Сплошной настил`.
- Детальный экран товара должен открываться полноэкранным fixed-слоем поверх текущей страницы, а не вставляться обычной секцией между блоками контента.
- Внутри полноэкранного товарного слоя нужно оставлять только саму карточку товара; блоки `Преимущества` и `Похожие товары` внутри модалки не показывать.
- Полноэкранный товарный слой должен визуально занимать почти весь viewport по ширине и высоте, а маленькие фото галереи внутри него должны быть квадратными.
- На страницах `/new.html` и `/used.html` товарные модалки должны быть одного и того же shell-стиля и размера: одинаковая ширина около `1000px`, одинаковая сетка, одинаковые внутренние панели; различается только контент товара.
- В модалке товара главное большое фото просмотра нужно держать в квадратной рамке `1:1`, а не в вытянутом прямоугольнике.
- В списке характеристик товара нельзя повторять одни и те же иконки для разных параметров; для `толщины`, `настила`, `размера`, `нагрузки`, `сорта`, `материала` и `качества` использовать отдельные знаки, сгенерированные через ImageGen.
- Для страницы новых поддонов у светло-бежевого hero-блока не нужен border-radius; левая CTA-кнопка должна быть без градиента, а правая CTA-кнопка прозрачной с серым бордером и серыми иконками.
- На странице новых поддонов правая hero-кнопка `Позвонить` в состоянии покоя должна быть полностью прозрачной, только с более толстым серым бордером.
- На странице новых поддонов между хедером и верхним hero-блоком не должно оставаться чёрной полосы; hero нужно поджимать вплотную под шапку.
- На странице новых поддонов сам стеклянный хедер нужно сохранять, но он должен лежать поверх hero-фото без отдельной чёрной полосы фона на всю ширину страницы.
- На странице новых поддонов стеклянный хедер должен быть фиксированным при прокрутке, оставаясь поверх hero-фото.
- В hero страницы новых поддонов правая вторичная CTA-кнопка должна быть `Позвонить` и вести на телефон, а не на прайс.
- На странице новых поддонов внутренние блоки нужно держать в одном тоне без разной прозрачности: использовать единый плотный фон панелей вместо набора полупрозрачных карточек с разным alpha.
- В каталоге на странице новых поддонов товарные карточки нужно делать полупрозрачными, сохраняя читаемый текст и аккуратный контур.
- Узкую плашку преимуществ под каталогом на странице новых поддонов нужно делать прозрачной, в стеклянном стиле.
- Карточки отзывов на странице новых поддонов тоже нужно делать прозрачными, в том же стеклянном стиле.
- Узкая плашка преимуществ и карточки отзывов на странице новых поддонов должны быть того же цвета и плотности, что и товарные карточки каталога.
- Узкую плашку преимуществ на странице новых поддонов нужно делать со скруглённым border-radius, чтобы она читалась как отдельная стеклянная карточка.
- У узкой плашки преимуществ на странице новых поддонов нужно держать минимальный внешний отступ 20px до краёв страницы.
- В hero страницы новых поддонов нужно использовать сгенерированные через ImageGen ассеты: отдельное фото паллеты, outline-иконки преимуществ и маленькие CTA-иконки.
- На странице новых поддонов сейчас нужно оставлять только верхний hero-блок без дополнительной секции с текстом и карточками ниже.
- Общий хедер сайта нужно подключать через EJS partial, чтобы одна и та же шапка переиспользовалась на всех страницах без копипаста.
- Ниже hero на странице новых поддонов нужно ставить тёмный каталог-блок на 4 карточки с заголовком по центру, тонкой золотой чертой, сгенерированными фото паллет, золотыми spec-иконками и outline-кнопкой `Подробнее`.
- Под каталогом нужно ставить узкую тёмную плашку на 4 колонки с золотыми outline-иконками, тонкими вертикальными разделителями и короткими тезисами про производство, качество, объёмы и доставку.
- Ниже плашки преимуществ нужно ставить блок отзывов на 3 карточки: тёмные карточки с золотой кавычкой, сгенерированными логотипами клиентов, именем, компанией и тремя точками навигации под секцией.
- На всей странице должен использоваться один общий складской фон на контейнере страницы; отдельные секции не должны получать свои собственные фоновые картинки как самостоятельные экраны.
- Для внутренних секций и карточек нужно избегать градиентных подложек: поверх общего фона страницы использовать только ровные однотонные панели без переходов по цвету.
- Фото паллет в hero и в карточках каталога нельзя подрезать по краям: для них всегда нужно оставлять безопасный контейнер и показывать изображение целиком.
- В desktop-каталоге карточки должны быть компактными и плотными: меньше пустого воздуха внутри, чуть крупнее текст и заметнее расстояние между самими карточками.
- В desktop-каталоге карточки нужно держать уже общей секции, а кнопку `Подробнее` ставить по центру каждой карточки.
- По клику на карточку товара нужно открывать большой детальный продуктовый экран в стиле референса: галерея слева, характеристики и CTA справа, ниже блок преимуществ и секция похожих товаров.
- Страница выбора вида поддонов должна быть одной цельной фотографией склада с диагональной разделительной линией, без отдельной черной плашки с текстом сразу под хедером.
- На странице выбора нужно собирать ровно два основных div-контейнера контента: `Новые поддоны` и `Б/у поддоны`; у левого блока все элементы, включая фото паллеты, прижимаются влево, у правого блока все элементы, включая фото паллеты, прижимаются вправо.
- В детальном экране товара главное фото в левой галерее должно читаться целиком и не подрезаться по краям; посадка ближе к каталожной съёмке с запасом внутри рамки.
- Для страницы б/у поддонов нужно собирать отдельный экран `/used.html` в том же визуальном языке: тёмный hero с крупной стопкой б/у паллет, каталог на 4 карточки, узкая плашка преимуществ, блок `Склад и качество`, отзывы и нижняя CTA-плашка.
- Нижнюю CTA-плашку на странице `/used.html` сейчас не показывать: экран б/у поддонов должен заканчиваться без отдельного финального CTA-блока.
- Верхний hero-блок на странице `/used.html` нужно держать глубоким чёрным с мягким тёмным градиентом и лёгкими тёплыми засветами, чтобы он не выглядел плоской чёрной плашкой.
- Во втором CTA hero-блока на странице `/used.html` подпись должна быть `Позвонить`, а не `Скачать прайс`.
- В каталоге б/у поддонов текущая схема 4 карточек должна быть такой: `120x800`, `120x100`, `120x120` и `Европоддоны с клеймом`; в карточках размеров нужно показывать толщину доски `19/20/22 мм` и варианты верхнего настила, а в карточке европоддонов с клеймом нужно раскрывать 1 сорт и 2 сорт с маркировкой `EUR, EPAL, UIC`.
- В детальном экране б/у поддонов у карточек `120x800`, `120x100` и `120x120` толщину доски и верхний настил нужно давать как переключаемые параметры, по той же схеме, что и у новых поддонов.
- Все кнопки `Оформить заявку` на страницах `/new.html` и `/used.html` должны открывать отдельную поверхностную модалку формы заявки в том же тёмном стеклянном стиле, с контекстом выбранного раздела, товара и выбранных параметров.
- В каталоге б/у поддонов карточки должны быть ещё плотнее, чем на странице новых: без лишнего описательного воздуха, с ценой `Цена от ...` внутри карточки и с кнопкой `Подробнее` на всю ширину нижней части карточки.
- Корень сайта должен быть отдельной страницей выбора поддонов в старом диагональном стиле: крупный заголовок и подзаголовок сверху, светло-тёмная диагональная сцена по центру, новые поддоны слева, б/у справа и нижняя стеклянная сервисная плашка.
- В общем хедере нужен постоянный переключатель между `/new.html` и `/used.html`; активный вид поддонов должен подсвечиваться прямо в шапке.
- Общий хедер нужно оформлять в том же визуальном языке, что и нижняя стеклянная плашка преимуществ: тёмный полупрозрачный фон, сильный blur, мягкая светлая обводка и максимально скруглённая форма.
- На странице выбора вида поддонов рядом со стопкой новых поддонов нужно показывать отдельный ящик из новых поддонов как дополнительный прозрачный ассет.
- На странице выбора вида поддонов левый товарный визуал нужно собирать одним общим изображением: стопка новых поддонов и ящик из новых поддонов без штампов `EPAL` и других маркировок на дереве.
- Для страницы выбора фоновую диагональную картинку нужно держать максимально простой: диагональная линия проходит строго через центр композиции, слева почти белый светлый фон для новых поддонов, справа почти чёрный фон для б/у поддонов.
- Для страницы выбора вида поддона в качестве фонового ассета сейчас использовать файл `public/assets/generated/home/backpoddon.png`.
- У фоновых ассетов страницы выбора и внутренних страниц не должно быть fixed/parallax-эффекта при прокрутке; фон должен скроллиться вместе со страницей.
- Для страницы выбора светлая и тёмная стороны диагонального фонового изображения должны быть равными по площади и визуально сбалансированными.
- Для страницы выбора светлая сторона диагонального фонового изображения должна иметь заметный тёплый жёлтый оттенок вместо нейтрально-белого.
- Для страницы выбора диагональная разделительная линия должна оставаться чёткой и чистой, без жёлтого блюра или светящегося ореола по центру.
- На правой стороне страницы выбора для б/у поддонов нужно использовать общий прозрачный ассет с двумя стопками б/у поддонов: большая сзади и меньшая спереди.
